# Синхронизация B2BHelp на хостинге

CLI-обработчик использует PHP 8.1+ с curl и pdo_mysql и существующую конфигурацию БД CRM. При необходимости передайте путь к ней через ELITESERVICE_CONFIG. Веб-запросы к обработчику получают HTTP 405.

На сервере создайте вне web-root файл b2b-sync-private.php с правами 0600 и доступом пользователя cron. Пример:

```php
<?php
return [
    'token' => 'ТОКЕН С ПРАВОМ acc_manager.list',
    'ledger_account' => 'ТОЧНОЕ НАЗВАНИЕ ИЗ ДНЕВНЫХ ОПЕРАЦИЙ CRM',
    'start_date' => '2026-11-25',
    'expense_field' => 'period_spend_total',
    'sole_contact_source' => false,
];
```

Перед запуском сверьте один закрытый день в кабинете с API: total включает другие расходы, from_ads учитывает только расходы на объявления. Выберите показатель, соответствующий журналу CRM. Флаг sole_contact_source разрешает заполнение общего числа контактов CRM только когда этот кабинет представляет весь учитываемый трафик. В остальных случаях число контактов сохраняется в снимке аккаунта.

В cron хостинга задайте запуск каждый час на 15-й минуте. Подставьте абсолютные пути к PHP CLI, размещённому обработчику, закрытой конфигурации и журналу вне web-root.

```cron
15 * * * * /path/to/php /path/to/crm-api/b2b-sync.php /private/b2b-sync-private.php >> /private/b2b-sync.log 2>&1
```

Обрабатываются завершённые московские дни. Расход и снимок дня записываются одной транзакцией. Повторный запуск пропускает внесённые дни. Журнал конфликтов требует разбора при пересечении с ранее внесённой рекламой. Включите уведомление о ненулевом коде выхода и ротацию журнала. Для приёмки сравните расход, показы, просмотры и контакты одного дня с B2BHelp, затем запустите повторно и убедитесь, что число операций и прибыль остались прежними. Корректировки источника после успешного импорта требуют отдельной сверки.
