## Open certification blockers

1. **Firestore Rules are not version-controlled in this repository.**
   No `firestore.rules`, emulator rules test suite or reproducible Firebase rules deployment is present.
   Anonymous denial is verified, but owner/dispatcher/master authorization and phone-unlock enforcement cannot be independently certified from Git.

2. **PIN-derived Firebase credential remains in the client.**
   Current HTML derives deterministic Firebase email/password values from login + PIN hash.
   This remains a security debt and does not satisfy the target authentication contract.

3. **Google Bridge secret remains inside the owner client trust boundary.**
   Current owner UI accepts the secret and `cloud.saveGoogle` stores it in Firestore config.
   This does not satisfy the target server-side-secret contract.

4. **No CI/CD release gate.**
   No `.github/workflows`, `package.json`, `tests/` or commit status checks exist on current main.
   Static parsing succeeds, but failing code is not mechanically prevented from deployment.

5. **No independently executed authenticated browser E2E in this audit.**
   The connected browser bridge is unavailable, so owner / dispatcher-logistic / master live sessions,
   server-side role isolation and phone time-gate were not re-executed here.

6. **Google synchronization needs an owner coordinator session.**
   The 18.17.18 patch only flushes Google delta queues when `cloud.profile.role === 'owner'`.
   Firestore remains canonical and realtime for operational users, but Google can lag while no owner session is open.
   On the next owner session dirty rows are recovered from baseline.
   This is safe but is not fully autonomous Firestore→Google delivery.

7. **Google→Firestore is not normal realtime synchronization.**
   Full reconciliation is deliberately `manual_only` for quota/data safety.
   Therefore direct editing of Google Sheets should not be treated as an automatically authoritative write path.

8. **PWA is manifest/install-UI based but has no service-worker registration.**
   Role manifests are valid and pages are mobile responsive; offline-capable PWA behavior is not implemented/verified.

9. **Restore gate is incomplete.**
   Code rollback and a verified Google data snapshot exist.
   An isolated full Firestore restore-and-compare test has not been independently executed, and managed Firestore backup/PITR is intentionally unavailable on Spark/no-billing.

10. **Production diagnostic mutation modes remain in owner HTML.**
    `?integrationDiag=create|delete|sync` still exists and is owner-session guarded.
    Target architecture requires mutation diagnostics to move to a restricted diagnostic surface.
